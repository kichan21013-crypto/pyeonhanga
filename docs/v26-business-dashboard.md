# 나가치 v26 — 사업 운영 대시보드

## 설치
기존 나가치 Supabase 프로젝트에서 백업 및 스키마 호환성을 확인한 뒤 [통합 설치 v26](../supabase/install-v26.sql)을 SQL Editor에서 실행합니다. v23~v25가 이미 적용되었다면 [v26 추가 SQL](../supabase/business-dashboard.sql)만 적용하면 됩니다. 관리자 계정 등록은 [v23 안내](v23-owner-db-setup.md)를 따릅니다. 실제 운영 SQL 실행과 Cloudflare 배포 확인은 GitHub 병합과 별개입니다.

## 운영실에서 보는 지표
운영 현황 > 사업 운영 지표 > 오늘 / 최근 7일 / 최근 30일 (한국시간, 오늘 포함).
- 동의 설문 기기: 기간 내 premium_willingness, demo 제외, 익명 브라우저 중복 제거.
- 모임 관심 기록: 모임×기기 단위, 마지막 동의 시각이 기간 내이고 현재 유효한 기록.
- 참가 신청 기록: 요청 시각이 기간 내인 현재 보관된 기록. 승인/승인 대기/대기자/운영자 취소 상태별 현재 수.
- 신청 대비 승인율: 현재 승인 기록 / 보관된 신청 기록. 분모 0이면 표시하지 않음.
- 지역/장소 TOP 10: 실제 동의 설문의 지역/장소별 서로 다른 브라우저 수.
- 모임/연결 코스 TOP 10: 신청 기록 우선, 관심 기록 차순. 코스 자체 조회수가 아님.
- 지불의향: 기간 내 브라우저별 마지막 동의 설문의 유효 응답. 1만원/2만원/3만원 이상 선택을 유료 의향으로 집계. 실제 결제율 아님.
- 서비스비 가정: 현재 승인 기록 × 직접 입력한 가정 전환율 × 1인 서비스비. 매출 실적이나 순이익 아님. 비용 포함 비교는 기존 수익 계획 메뉴.

## 해석 주의
기존 앱은 동의 전 방문/검색/조회 이벤트를 서버에 저장하지 않습니다. 전체 방문자, 코스 조회수, 방문 대비 가입률은 집계할 수 없습니다. 설문·관심·신청의 기기 식별값이 서로 달라 개인 수준 관심→신청 전환율은 산출하지 않습니다. 일별 표는 현재 남아 있는 기록의 날짜별 분포이며 취소/삭제·재등록 등으로 과거 수치가 변할 수 있습니다. 실제 사람 수, 출석률, 누적 신청 이벤트 이력, 결제액이 아닙니다. 신규 추적이나 연결 식별자를 추가하지 않습니다.

## 검증
- 익명/일반 Auth 사용자 RPC 거부, 등록된 관리자만 집계 조회.
- 오늘/7일/30일 KST 기준, 기간 밖 및 demo 설문 제외, 최신 지불의향 중복 제거.
- 0건 정상 반환과 연결 오류 구분, 분모 0이면 비율 —.
- 모임 신청 승인·취소·삭제 후 집계 변화, 코스/지역/장소 순위 확인.
- 로그아웃 시 대시보드 삭제, 늦게 도착한 응답이 이전 세션 정보를 표시하지 않음.
- 실제 운영 DB/실기기 검증 전에는 지표를 운영 판단에 사용하지 않음.
