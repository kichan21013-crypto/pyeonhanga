# 나가치 v19 · 무료 동행 관심 그룹 / 앱 내 공지 운영 방법

## 무엇이 실제로 작동하나요?
- '같이갈래?'를 누르면 활동 4종의 제목으로 스크롤합니다. 사진은 기존 공개 장소 데이터에서만 불러옵니다.
- 동의한 설문 제출 후 **실제 서로 다른 브라우저에서 남긴** 활동별 관심 수를 집계합니다. 5건 미만은 공개하지 않습니다.
- 희망자는 **별도로 '이 기기에서 동행 소식 보기'에 동의**할 수 있습니다. 이름·휴대전화·이메일은 수집하지 않습니다.
- 운영자는 취향 활동별 관심 수와 별도 수신 신청 기기 수를 보고 **모임 준비 공지**(일시·모일 곳)를 작성합니다.
- 공지는 선택한 활동의 신청 기기에 **앱 재방문 시에만** 표시됩니다. 푸시·문자·이메일은 발송되지 않습니다.
- 현재 사용자 계정·실명·개별 파티원 명단·동의한 사람에게 전화/문자 발송·실제 모집확정 기능은 **없습니다**.
- 이름·연락처 없는 익명 의향 데이터만으로는 특정 사람에게 직접 연락할 수 없습니다. 추후 연락 기능이 필요하다면 별도 검증과 구분된 동의를 거쳐야 합니다.
- **무료 유지**: GitHub, Cloudflare Workers, Supabase Free 범위만 사용하며 신규 패키지/유료 API는 추가하지 않았습니다.

## 실제 데이터 연결: 운영자가 할 일
운영 정보는 GitHub만 병합해도 자동으로 서버에 쌓이지 않습니다. **현재 Supabase Free 프로젝트가 실제로 연결돼 있는지 먼저 확인해야 합니다.**

1. Supabase 프로젝트의 SQL Editor에서 기존 `supabase/schema.sql` 적용 여부를 확인합니다. 이미 40~44·45~49세가 허용돼 있어야 합니다.
2. 같은 프로젝트 SQL Editor에서 새 `supabase/companion-groups.sql` 파일을 검토하고 직접 한 번 실행합니다. 실사용 DB 백업과 안전성 확인을 먼저 진행합니다.
3. **관리자만** Supabase Dashboard > Authentication > Users에서 본인의 Auth 계정을 생성(또는 기존 계정을 사용)합니다. 자동으로 공개 사용자가 관리자가 되지 않습니다.
4. SQL Editor에서 본인의 `auth.users.id`를 확인한 후 다음 명령의 UUID 부분을 **본인 실제 ID로 교체해 직접 실행**합니다.

```sql
insert into public.nagachi_companion_admins (user_id)
values ('본인-Supabase-Auth-UUID') on conflict do nothing;
```

5. 운영자의 공개 앱 주소 뒤에 `/admin.html`을 붙여 접속합니다. Supabase Auth 이메일·비밀번호로 로그인 후 활동별 관심 수, 공지 수신 기기 수, 공지 초안/게시 화면이 보입니다.
6. 예를 들어 **'맛있는 한 끼'**를 대상으로 제목, 공지 내용, 예정 시각, 모일 장소를 작성합니다. 기본은 초안으로 사용하고 실제 게시하려면 '공지로 게시하기'를 선택합니다.
7. 다른 기기에서 '맛있는 한 끼' 활동을 관심 등록하고, **별도 소식 수신 동의**도 완료한 뒤 홈의 '내가 고른 동행 소식'에서 공지가 보이는지 확인합니다.
8. 관심 인원은 '실제 참석 확정'이 아니라 '동의 후 익명 관심 의사'입니다. 5명 미만은 공개 화면에서 '관심 집계 중'으로 표시될 수 있습니다.

## 개인정보·안전
- 공개 `apikey`만 브라우저에 노출됩니다. Supabase `service_role`/secret 키는 절대 프런트엔드에 넣지 않습니다.
- 실제 관리자 접근 권한은 공개 페이지 주소가 아니라 DB 내 `auth.uid()`·관리자 허용 목록으로 검사합니다.
- 공지 수신용 비밀 토큰은 256비트 난수로 생성해 **해시만 서버에 저장**합니다. 원본은 이용자의 브라우저에만 저장됩니다.
- 구독 수신 자격은 **90일간 유효**하며, 만료 구독 기록은 관리자가 정리합니다. 이용자가 해지하면 서버에서 해당 익명 구독 데이터를 즉시 삭제합니다. 기기/브라우저 기록 삭제 시 재조회가 불가능할 수 있습니다.
- 공개 관심 인원 수에는 작은 집계를 표시하지 않습니다. 관리자는 정확한 관심 브라우저 수를 볼 수 있지만 누구인지 알 수 없습니다.
- 실제 모임 진행에 앞서 참가자 안전, 만남/연락에 대한 동의, 개인정보 처리방침, 여행업 관련 등록 여부, 유상 교통 알선 금지 등 법률 검토가 추가로 필요합니다. 현 버전은 실제 운송·여행업·예약·결제 기능이 없습니다.
- 본 기능은 실제 모임 알림 **발송 서비스가 아닙니다**. 앱 안에 게시물을 만들어 수신 동의한 기기에만 반환하는 기능입니다.

## 브라우저 검증
```bash
npm run build
npm test
```
브라우저 실사(별도 Playwright 설치 환경에서만): `TEST_URL=https://실제서비스주소 node tests/browser-smoke.mjs`

GitHub 자동 빌드 성공 ≠ Cloudflare 배포 성공 ≠ Supabase 실 DB 함수 실행 성공. 세 항목은 각각 확인해야 합니다.
