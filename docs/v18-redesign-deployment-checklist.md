# 나가치 v18 디자인 및 연령 옵션 적용 안내

## 개발 변경 사항
- 홈: 따뜻한 커피 풍경 일러스트, 깊은 그린/코랄 컬러와 선명한 CTA.
- 활동: 카테고리 아이콘 4개를 앱 내 로컬 오리지널 SVG 일러스트로 대체.
- 장소: 관광공사 실제 사진과 이름을 사용하고 장소 선택 시 기존 동행 희망 흐름 유지.
- 취향 입력: 모바일에서 편하게 누를 수 있는 2단계 선택 카드(연령·함께할 사람·목적 / 인원·서비스비·동의).
- 40~44, 45~49 선택지 추가. 앱의 노출 연령 제한을 50+로 안내하지 않음.
- 결혼 여부·혼인·데이트를 강조하는 문구 삭제. 실명/연락처 미수집, 결제/매칭/차량 배차 미제공.
- 코어 HTML/CSS/JS 캐시 버전: `20261124-v18`; 외부 디자인 라이브러리·유료 API 미사용.

## 실제 운영 DB: 추가 조치가 필요한 경우
이미 Supabase Free 프로젝트에서 `public.record_event` 함수를 실행 중이라면, 예전 서버는 40대 연령을 거부할 수 있습니다. GitHub 수정만으로 Supabase 함수가 자동 갱신되지는 않습니다.

연결된 프로젝트의 **Supabase SQL Editor**에서 이 저장소의 최신 `supabase/schema.sql` 전체를 확인한 후 적용하세요. 이 스크립트는 기존 테이블과 데이터를 보존하고 `record_event`의 허용 연령 목록을 확장하도록 작성돼 있습니다. 실행 전에 프로젝트/데이터 백업 여부를 확인하고, 가능한 경우 비운영 프로젝트에서 먼저 검증하세요.

- 허용 연령: `40~44`, `45~49`, `50~54`, `55~59`, `60~64`, `65~69`, `70+`
- 서버는 기존의 입력 항목, UUID, 이벤트 유형, 데이터 크기 제한 및 최소 수집 원칙을 그대로 유지합니다.
- 운영 환경 설정 `SUPABASE_URL`과 `SUPABASE_ANON_KEY`가 미입력인 경우 동의하더라도 **응답이 서버에 저장되지 않음**을 화면에 표시합니다. 비공개 service-role key는 프런트엔드 빌드에 사용하지 마세요.
- 개인정보 보호: 동의 전 방문/활동 클릭 로그를 서버로 보내지 않고, 동의한 응답만 전송합니다.

## 실제 기기 검증
1. Cloudflare에 최신 소스가 배포되었는지 확인합니다. GitHub CI 통과 자체는 배포 성공을 의미하지 않습니다.
2. 모바일 사파리에서 홈 카드 사진/선택 테두리/가로 스크롤 없음 확인.
3. '같이 맛있는 거 먹으러 갈 사람?' → 실제 음식점 카드 → '여기, 같이 가보고 싶어요' 선택.
4. 연령대 `45~49`를 포함해 라디오 카드를 선택하고 다음 단계 이동 및 뒤로 가기 확인.
5. 동의 선택 → 실제 저장 성공 또는 미연결 안내가 사실대로 표시되는지 확인.
6. 관리자가 Supabase 데이터에 동의한 테스트 응답이 단 한 건 기록되는지 확인하고, 테스트 응답은 개인정보 정책에 맞게 정리합니다.

무료 운영 원칙: 기존 Cloudflare Workers Static Assets/GitHub/Supabase Free 한도 내에서만 사용합니다. 디자인용 SVG 파일은 저장소에 포함되며 외부 결제나 별도 호출을 일으키지 않습니다.
