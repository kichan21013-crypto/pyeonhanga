# 나가치 v20 · 동행 관심 등록 중심 화면 및 저장 실패 대응

## 실제 앱에 적용한 사용자 경험
- 2단계 상단에 “이 동행에 관심 있어요!” 중심 메시지 배치.
- 선택한 활동별 현재 저장된 익명 관심 수를 보여주되, **다섯 명 미만은 공개하지 않고 활동 간 합산하지 않음**.
- 서비스비 의향은 선택적으로 펼쳐보는 영역으로 이동. 미선택 시 **'아직 모르겠음'으로 기록**됨을 명시.
- 별도 “동행 소식도 보고 싶어요” 체크는 사용자가 직접 결정. 기본 비선택.
- 오렌지 코랄 주요 CTA “♡ 이 동행에 관심 있어요”를 하단에서 시각적으로 강조.
- 미저장 결과를 완료 화면으로 보내지 않고 **오류 유형을 안내하며 선택값과 재시도 버튼 유지**.
- 개인정보 동의와 실제 저장 성공을 구분. 사용자 클릭수와 서버 관심 지표를 혼동하지 않음.

## 사용자 iPhone에서 관찰한 문제
스크린샷에 “저장되지 않았어요. 연결 상태를 확인하고 다시 시도해 주세요.” 문구가 노출됨. 이 증상은 UI 버그만으로는 해결되지 않으며 **Supabase 저장 요청을 거절하거나 접속할 수 없는 상황**일 수 있습니다. 실제 오류 코드와 운영 Supabase 프로젝트 권한이 보이지 않아 어느 원인인지는 확정하지 못했습니다.

## 새 저장 실패 안내
| 분류 | 앱 메시지 취지 | 관리자의 확인 사항 |
| --- | --- | --- |
| 서버 미설정 | 저장 서버 연결 전 | Cloudflare/GitHub build env: SUPABASE_URL, SUPABASE_ANON_KEY |
| RPC 404/PGRST202 | 저장 기능 준비되지 않음 | SQL Editor에서 `supabase/schema.sql` 적용, `record_event(jsonb)` 존재 여부 |
| HTTP 401/403 | 권한 오류 | anon/publishable key 유효성, `grant execute on function public.record_event(jsonb) to anon` |
| HTTP 400/409/422 | 데이터 규칙 불일치 | DB 스키마의 연령(40~49 추가), activities 배열, allowed detail keys, required survey values |
| 네트워크/시간초과 | 일시 연결 문제 | 네트워크, Supabase 프로젝트 상태, CSP |
| 5xx/기타 | 서버 문제 | Supabase logs; DB project 오류 |

이 분류는 사용자 응답 원본·비밀키·서버 상세 에러를 콘솔 또는 별도 서버로 전송하지 않고 HTTP 응답 코드만 브라우저 내부에서 사용합니다.

## 실제 저장을 확인하는 방법
1. GitHub PR 병합과 Cloudflare 반영은 별도로 확인합니다. URL 버전 `20261124-v20`이 노출되는지 확인합니다.
2. 운영 프로젝트에 최신 `supabase/schema.sql`이 설치됐는지, `analytics_events`가 존재하는지 확인합니다.
3. 설치된 경우 **본인 기기에서만** 동의 후 테스트를 1건 제출합니다. 성공 메시지가 떠야 합니다.
4. Supabase SQL Editor에서 `premium_willingness` 최근 기록 1건과 `details.activities`, `details.age`를 확인합니다. 이름/연락처 저장은 없어야 합니다.
5. 본인 테스트 데이터는 개인정보 보존 정책에 맞춰 정리하고, 실제 운영 결과에 테스트 기록이 섞이지 않도록 관리합니다.
6. 운영자 관심 집계를 쓰려면 `supabase/companion-groups.sql`도 별도로 설치하고 실제 관리자 Auth 허용 계정을 설정해야 합니다.

참고: CI 테스트는 **의도적으로 가짜 Supabase 응답을 사용**합니다. 로컬/CI 통과는 실제 서버 저장 성공을 뜻하지 않습니다. 신규 유료 서비스·패키지나 문자/푸시 비용은 추가하지 않았습니다.
