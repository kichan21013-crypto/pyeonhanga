# 나가치 운영실 v22 — 비개발자를 위한 사용 안내

## 1. 운영실 입장 주소
홈페이지는 지금까지와 같고, **관리자만 사용할 화면**은 아래 주소입니다.

`https://pyeonhanga.kichan21013.workers.dev/admin.html`

주소를 아는 것만으로 관리할 수는 없습니다. 이 주소는 공개 정적 페이지일 수 있지만 **데이터 조회·저장은 Supabase Auth 사용자 로그인과 DB 관리자 허용 목록 모두 통과한 계정만** 가능합니다. 사용자용 홈에 관리자 링크를 노출하지 않습니다. 비밀번호/세션을 브라우저 저장소에 영구 저장하지 않습니다.

## 2. 관리자 계정을 처음 연결할 때 필요한 설정

**중요:** GitHub에 코드를 병합했다고 해서 Supabase 운영 DB가 자동으로 연결되지는 않습니다. 기존에 확인된 “저장되지 않았어요” 문제는 별개로 먼저 점검해야 합니다.

1. 본인이 관리하는 **Supabase Free 프로젝트**에 로그인합니다. 이미 연결한 프로젝트가 없다면 새로 만들되, 무료 플랜 범위와 운영 환경 설정을 확인합니다.
2. 프로젝트의 **SQL Editor**에서 `supabase/schema.sql`을 검토하고 기존 테이블/데이터를 보호하며 설치합니다. 현재 동행 응답 저장 실패가 있다면 이 부분부터 확인합니다.
3. 같은 DB에서 `supabase/companion-groups.sql`을 설치합니다. 여기에는 운영자 허용 목록 및 기존 관심자 공지 기능이 포함됩니다.
4. 신규 `supabase/operations-studio.sql`을 설치합니다. 코스·모임·수익 계획용 비공개 테이블 및 관리자 저장 함수가 포함됩니다.
5. **Authentication > Users**에서 본인의 이메일로 로그인할 사용자 계정을 만듭니다. 외부인이나 일반 이용자에게 관리자 계정 발급을 열어놓지 않습니다.
6. SQL Editor에서 `auth.users`의 **본인 사용자 UUID**를 확인한 뒤 다음 예시의 UUID를 실제 값으로 바꿔 실행합니다.

```sql
insert into public.nagachi_companion_admins(user_id)
values ('본인-Auth-사용자-UUID') on conflict do nothing;
```

7. `/admin.html`에서 등록한 이메일·비밀번호로 로그인합니다. **로그인 성공, 운영 자료 읽기, 새 코스 초안 저장**을 차례로 확인합니다.
8. 보안을 위해 `nagachi_companion_admins`에 본인 외 다른 UUID가 없는지 확인합니다. 관리자 허용 목록에 등록한 계정만 권한이 있습니다.
9. Supabase 프로젝트 URL과 공개 publishable/anon 키가 Cloudflare 실제 배포에서 `config.js`로 연결됐는지 확인합니다. **service_role/secret 키는 절대 웹앱에 넣지 마세요.**

## 3. 네 가지 운영 메뉴 사용법

### 운영 현황
기존 서버에 실제로 저장된 익명 동행 관심 수, 별도 공지 수신을 신청한 기기 수, 본인이 만든 코스/모임/사업성 시나리오 현황을 확인합니다.

**주의:** 관심 5명 ≠ 실제 참가 확정 5명입니다. 현재는 이름·연락처·개인별 명단이 없습니다.

### 코스 만들기
- 코스 이름 → 음식·산행·산책·여행 선택 → 지역/소요시간 선택
- 코스 설명에 일정을 작성하고 **실제 장소 636곳** 중 이름으로 검색해 최대 5곳을 추가합니다. 추가 순서가 코스 순서입니다. 주행 거리·이동시간은 자동 계산하지 않습니다.
- 처음에는 **비공개 초안**으로 저장합니다.
- 내용을 확인한 뒤 “이 코스를 일반 앱에 공개하기”를 체크하고 저장하면 사용자 홈의 **“나가치가 제안하는 동행 코스”** 영역에 실제 장소 사진과 함께 노출됩니다.
- 수정 버튼으로 편집할 수 있고 공개 체크를 해제한 뒤 저장하면 비공개로 전환됩니다.

### 동행 모임
- 모임 이름·활동·연결할 코스·소개·예정 시각·선호 인원·모일 곳을 작성합니다.
- **내 초안 / 구성 준비 / 준비 소식 공개 / 마감**으로 진행 상태를 관리합니다.
- '준비 소식 공개'를 선택하면 이용자에게 **모임 제안**이 노출되지만, 참가 신청/참가 확정은 아닙니다.
- 정확한 집결 장소는 공개 목록의 응답에서 제외합니다.
- 기존 **“해당 관심자 공지”** 버튼으로 모임 안내 초안을 만들 수 있습니다. 직접 공개를 선택한 뒤 저장해야 수신 동의한 활동의 기기에서 앱 재방문 시 확인 가능합니다. **자동 문자·푸시·이메일 발송은 없습니다.**
- 지금은 익명 브라우저 관심을 집계할 뿐 개인별 파티원 명단이나 참가 신청/연락 수단은 제공되지 않습니다.

### 수익 계획
- 모임당 인원, 월 모임 횟수, 1인 서비스비, 예상 유료 전환율, 모임당 운영비를 입력합니다.
- 실시간으로 **예상 유료 참여 인원, 예상 서비스비 매출, 운영비, 차감 후 예상 잔여액**을 표시합니다.
- 계획을 여러 개 만들어 비교·수정할 수 있지만 **비공개 가정 데이터만 저장**합니다. **실제 결제·정산·세금·확정 매출** 기록은 없습니다.
- 식비·카페비·입장료·교통비는 개인이 직접 결제하는 기존 사업 구상과 분리해서 시나리오를 검토합니다.
- 법적 등록, 영업 구조, 안전 책임, 약관, 개인정보와 유상 교통/여행상품 관련 규정은 **실제 운영·유료화 전에 전문 검토**가 필요합니다.

## 4. 아직 제공하지 않는 기능 / 유료화 전에 필요한 다음 개발
- 실제 참가 신청, 참가 승인, 개인정보 제공에 대한 별도 동의
- 개인별 파티원 구성과 안전 확인, 개별 공지, 취소/환불 정책
- 모임 참가·불참 기록, 결제·정산·세금계산

이 기능들은 **단순한 관심 수요 설문과 명확히 구분**해 개인정보·안전·법률·비용을 검토한 뒤 도입해야 합니다. 이번 버전에는 실제 참가자 데이터베이스나 결제 시스템을 만들지 않았습니다.

## 5. 검증
- 빌드 `npm run build` 및 자동 테스트 `npm test`가 성공하더라도, 이것은 실제 Supabase 운영 SQL 실행과 Cloudflare 실배포 검증을 대신하지 않습니다.
- 운영자 전용 기능의 저장/수정/게시를 실제 Supabase Free 프로젝트에서 한 차례 테스트한 뒤 사용하세요.
- SQL과 프런트엔드 코드는 GitHub에서 보관하며 신규 유료 API·외주·문자 발송·결제 서비스는 추가하지 않습니다.
